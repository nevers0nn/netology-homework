## Задача 2

### 1. Высоконагруженная MySQL, критичная к отказу

**Выбор: физические серверы**

Причины:

* максимальная производительность CPU, RAM и дисков;
* нет конкуренции за ресурсы с другими ВМ;


### 2. Различные web-приложения

**Выбор: виртуализация уровня ОС, например Docker/LXC.**

Причины:

* низкие накладные расходы;
* быстрый запуск;
* удобное масштабирование;
* высокая плотность размещения приложений.


### 3. Windows-системы для бухгалтерского отдела

**Выбор: паравиртуализация**

Причины:

* можно запускать полноценные Windows-системы;
* хорошая изоляция между пользователями и виртуальными машинами;
* удобно создавать резервные копии и snapshots;
* можно централизованно управлять системами;
* проще восстанавливать рабочее окружение при сбоях.

Для Windows-инфраструктуры логично использовать Hyper-V.

### 4. Высокопроизводительные расчёты на GPU

**Выбор: физические серверы.**

Причины:

* прямой доступ к GPU;
* максимальная производительность;
* меньше накладных расходов;
* проще работать с CUDA и специализированными драйверами.


### Итог

| Задача                  | Платформа              |
| ----------------------- |------------------------|
| Высоконагруженная MySQL | Физические серверы     |
| Web-приложения          | Виртуализация уровня ОС |
| Windows для бухгалтерии | Паравиртуализация      |
| GPU-вычисления          | Физические серверы     |

## Задача 3

### 1. 100 Linux и Windows ВМ, преимущественно Windows

**Выбор: Hyper-V.**

Причины:

* хорошая интеграция с Windows Server;
* поддержка Linux и Windows;
* Live Migration;
* репликация;
* автоматизация через PowerShell;
* удобное централизованное управление.

### 2. 20–30 Linux и Windows ВМ, бесплатное open source решение

**Выбор: KVM/QEMU + Proxmox VE.**

Причины:

* open source;
* высокая производительность;
* поддержка Linux и Windows;
* web-интерфейс;
* кластеризация;
* резервное копирование;
* live migration.

### 3. Бесплатное и производительное решение для Windows

**Выбор: Hyper-V.**

Причины:

* высокая совместимость с Windows;
* хорошая производительность;
* интеграция с Windows Server;
* PowerShell;
* поддержка миграции и кластеризации.

### 4. Тестирование ПО на нескольких Linux-дистрибутивах

**Выбор: VirtualBox.**

Причины:

* бесплатный;
* простой в использовании;
* поддерживает разные Linux-дистрибутивы;
* есть snapshots и клонирование ВМ;
* хорошо подходит для локальных тестовых стендов.

### Итог

| Сценарий               | Решение            |
| ---------------------- | ------------------ |
| 100 Linux/Windows ВМ   | Hyper-V            |
| 20–30 ВМ, open source  | KVM/QEMU + Proxmox |
| Windows-инфраструктура | Hyper-V            |
| Тестирование Linux     | VirtualBox         |

## Задача 4

Гетерогенная среда — это использование нескольких платформ виртуализации одновременно, например Hyper-V, VMware и KVM.

Основные проблемы:

* сложнее администрировать;
* разные форматы дисков: VMDK, VHDX, QCOW2;
* сложнее переносить ВМ между платформами;
* разные системы резервного копирования;
* сложнее мониторинг;
* сложнее автоматизация;
* выше требования к квалификации администраторов;
* выше стоимость сопровождения.

Для минимизации проблем необходимо:

* стандартизировать использование платформ;
* применять Terraform и Ansible;
* использовать единый мониторинг;
* централизовать логирование;
* документировать инфраструктуру;
* по возможности использовать единую систему резервного копирования.

Если бы был выбор, я бы использовал **одну платформу виртуализации**.
